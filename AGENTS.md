# AGENTS.md

Guidance for AI coding agents working in this repo. Humans: see [README.md](README.md) and [docs/CI_CD.md](docs/CI_CD.md).

## What this is

Pyre is a non-custodial wallet cleaner for **Robinhood Chain (chain id 4663)**. It burns spam, revokes leftover approvals and sweeps quoted junk to ETH, while **Stock Tokens and stables stay locked**. It handles real user funds, so correctness beats cleverness.

- **App:** React 19, TanStack Start/Router, Vite, Tailwind CSS v4, viem + wagmi, sonner. Deployed on Vercel (Nitro v3).
- **Contract:** `contracts/PyreBatch.sol`, live at `0xcB157e4D7035F9a38b9e0B92b89E544e378c1490`. It only collects the batch fee.

## Commands

```bash
npm install            # .npmrc sets legacy-peer-deps
npm run dev            # http://localhost:8080
npm run ci             # lint + typecheck + unit tests + build (same as CI)
npm run test:app       # node --experimental-strip-types --test 'src/**/*.test.ts'
npm run test:contracts # cd contracts && forge test
contracts/script/verify-deployment.sh   # live bytecode + settings check
```

Before you finish a change, run `npm run ci`. If you touched `contracts/`, also run `npm run test:contracts`. CI blocks on lint, typecheck (0 errors), unit tests, build, forge tests and CodeQL.

## Rules for fund-handling code (`src/lib/web3/`, `contracts/`)

- **Never weaken the Stock Token lock.** Protected assets must never be selectable for burn. If the registry fails to load, fail closed.
- **Never charge more than the user saw.** The batch fee is read on-chain at sign time (`resolveBatchFee`), and a higher fee must stop the clean.
- **Keep every safety step:** simulate before signing, check the receipt after, and if the fee fails no burns start.
- **Add or update tests** in `src/lib/web3/*.test.ts` for any behaviour change, and keep diffs minimal and easy to review.
- **Do not edit `contracts/PyreBatch.sol` casually.** It must stay byte-identical to the deployed contract (solc 0.8.37, optimizer off). A real change means a redeploy, new tests, and updates to `contracts/README.md`, `LIVE_PYRE_BATCH` in `src/lib/web3/fees.ts` and the README deployment tables.
- Never commit keys, `.env` files or RPC secrets.

## Code conventions

- **Imports inside `src/lib/web3/` use explicit `.ts` extensions** (`./chain.ts`) so Node's test runner can load them. Elsewhere use the `@/` alias.
- **Pure modules that have tests must not import via `@/`**, because Node can't resolve the alias. Use relative `.ts` paths or type-only imports, as in `src/components/cleaner/outcome.ts`.
- **`.tsx` files export components only** (react-refresh rule). Put data, constants and helpers in a sibling `.ts` file (e.g. `cleaner/modes.ts`, `cleaner/steps.ts`).
- **Status regions using `<output>` need an explicit display class** (`block` or `flex`). `<output>` is inline by default and the layout collapses without it.
- **User feedback goes through Pyre's helpers:** `notify.success/error/warning/info` for toasts, `confirmDialog`/`alertDialog` for modals, and `Notice` for inline messages. Don't call `sonner` directly or use `alert()`.
- **Error text** comes from `actionErrorMessage`, `scanErrorMessage` or `connectErrorMessage` in `src/lib/web3/tx-error.ts`. Add rules there, with tests, rather than showing raw errors.
- **Styling** uses the tokens in `src/styles.css` (`--color-primary` lime `#ccff00`, `--shadow-border`, `--shadow-hairline`, `text-link`) and the existing primitives. Keep motion behind `prefers-reduced-motion`.
- **Formatting:** Prettier (`.prettierrc`). Format only the files you change. Many older files are unformatted, and reformatting them buries real diffs.
- **Copy:** plain, short and honest. Don't claim things the code can't back up, such as "verified" or "most used".

## Git

- **One-line Conventional Commits, no body**, e.g. `fix(web3): stop fee read when contract is missing`. Common scopes: `web3`, `cleaner`, `ui`, `fees`, `contracts`, `server`, `docs`, `ci`.
- **Branch from `main` and open a PR.** CI must be green, and Vercel posts a preview link.
- **Stage only the files you meant to change.** Never use `git add -A` over unrelated edits.
